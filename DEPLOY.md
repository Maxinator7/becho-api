# Deploying the Becho staging environment (free tier)

| Part | Service | Notes |
|---|---|---|
| Database | Neon (free) | 1 GB, scales to zero after 5 min idle |
| API | Render web service (free), from `render.yaml` | Sleeps after 15 min idle; the first request after that takes about a minute |
| Web | Cloudflare Workers static assets (free) | Static Vite build, config in `becho-web/wrangler.jsonc` |
| Mobile | Expo Go | `EXPO_PUBLIC_API_URL` points at the Render URL |

This is a **test environment**. OTP codes are shown on screen (`EXPOSE_DEV_OTP=true`), because no SMS provider is set up yet.

## 1. Neon: database
1. Create a project in the **AWS Asia Pacific (Singapore)** region, with Postgres 16.
2. Under **Connect**, turn **Connection pooling OFF** and copy the direct connection string. Prisma migrations need the direct connection.
3. Append `&connect_timeout=15` so the first query after Neon wakes from idle doesn't time out:
   `postgresql://USER:PASSWORD@ep-xxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require&connect_timeout=15`

## 2. Render: API
1. **New → Blueprint**, then connect the GitHub repo `Maxinator7/becho-api`. Render reads `render.yaml`.
2. When prompted, fill in:
   - `DATABASE_URL`: the Neon string from step 1.
   - `CORS_ORIGINS`: the Cloudflare URL from step 4, e.g. `https://becho-web.<account>.workers.dev`. If you don't know it yet, enter a placeholder and update it later.
3. Deploy. Every start runs `prisma migrate deploy`, which applies pending migrations. Check that `https://<service>.onrender.com/api/v1/health` returns `"status":"ok"`.

`JWT_SECRET` and `JWT_REFRESH_SECRET` are generated by Render.

## 3. Load the starter data (once, from your machine)
```bash
cd becho-api
DATABASE_URL='<neon string>' SEED_PASSWORD='<a non-default password>' npm run seed
```
This creates the cities, categories, demo listings and three demo users: aarav@example.com, priya@example.com and admin@becho.in. Running it again is safe. The URL is public, so use a real password, not `password123`.

## 4. Cloudflare: web
1. **Workers & Pages → Create → Import a repository**, then pick `Maxinator7/becho-web`, branch `main`.
2. Build command `npm run build`; deploy command `npx wrangler deploy` (the default). `wrangler.jsonc` tells it to serve `dist/` as a single-page app.
3. The API URL comes from `becho-web/.env.production` (committed; it is public in the bundle anyway). Node 20 comes from `.nvmrc`. No Cloudflare variables are needed, and a static-assets Worker can't have runtime variables anyway.
4. Copy the `*.workers.dev` URL into Render's `CORS_ORIGINS` (Render restarts automatically).

To point the web at another API, edit `.env.production` and push.

## 5. Mobile: Expo Go
```bash
cd becho-mobile
EXPO_PUBLIC_API_URL=https://<service>.onrender.com/api/v1 npx expo start
```
CORS doesn't apply to the mobile app.

## 6. Cloudflare R2: photo and video storage
Render's disk is wiped on every restart, so uploaded media must go to R2. Until this is done the API stores files locally and they disappear on redeploy.

1. **R2 → Create bucket**: name `becho-media`, location hint **Asia-Pacific**.
2. Bucket → **Settings → Public access → R2.dev subdomain → Allow**. Copy the `https://pub-….r2.dev` URL. (Later: connect a custom domain such as `media.becho.in` instead; r2.dev is rate-limited and meant for testing.)
3. Bucket → **Settings → CORS policy → Add**, so browsers can upload directly:
   ```json
   [
     {
       "AllowedOrigins": ["https://becho-web.gautamwarmachine68.workers.dev", "http://localhost:3000"],
       "AllowedMethods": ["PUT", "GET", "HEAD"],
       "AllowedHeaders": ["Content-Type"],
       "MaxAgeSeconds": 3600
     }
   ]
   ```
4. **R2 → Manage API tokens → Create API token**: permission **Object Read & Write**, limited to the `becho-media` bucket. Copy the Access Key ID and Secret Access Key (shown once). The Account ID is on the R2 overview page.
5. Render → becho-api → **Environment**, add:
   `STORAGE_DRIVER=r2`, `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET=becho-media`, `R2_PUBLIC_URL=https://pub-….r2.dev`

The API refuses to start if `STORAGE_DRIVER=r2` and any R2 value is missing, so a typo shows up in the Render logs immediately.

**Limits** (env vars on Render, defaults in brackets): photo size `MEDIA_MAX_IMAGE_MB` (5), video size `MEDIA_MAX_VIDEO_MB` (50), video length `MEDIA_MAX_VIDEO_SECONDS` (60), photos per listing `MEDIA_MAX_IMAGES_PER_LISTING` (10), videos per listing `MEDIA_MAX_VIDEOS_PER_LISTING` (1), uploads per user per day `MEDIA_UPLOADS_PER_DAY` (100), new listings per user per day `LISTINGS_PER_DAY` (5). Uploads never attached to a listing are deleted after 24 hours.

## 7. Cloudflare: admin portal (separate from the marketplace)
The admin portal is its own app, built from `becho-web` (`npm run build:admin` → `dist-admin/`) and deployed as a second Worker, so the public site contains no admin code.

1. **Workers & Pages → Create → Import a repository** → `Maxinator7/becho-web` again, branch `main`, Worker name **`becho-admin`**.
2. Build command: `npm run build:admin`. Deploy command: `npx wrangler deploy --config wrangler.admin.jsonc`.
3. After the first deploy, copy the URL (`https://becho-admin.<subdomain>.workers.dev`) and **add it to Render's `CORS_ORIGINS`** (comma-separated, after the marketplace URL), plus the R2 CORS list if staff will upload.
4. **Lock it down with Cloudflare Access (free for up to 50 users):** Worker → **Settings → Domains & Routes** → on the `workers.dev` row choose **Enable Cloudflare Access**. Then in **Zero Trust → Access → Applications** edit the generated policy to allow only your staff emails. Visitors must prove they own an allowed email (one-time code) before the admin page even loads; the API still checks the admin role on every request.

Later, with a custom domain (e.g. `becho.in`): marketplace at `becho.in`, admin at `admin.becho.in`, media at `media.becho.in`.

## Known limits of this setup
- **Cold starts:** the API sleeps when idle, and the first request after that takes about a minute. Render Starter ($7/month) removes this.
- **Background jobs only run while the API is awake.** The in-process scheduler expires listings and offers. Expiry catches up on the next wake-up.
- **No persistent disk on Render.** Image uploads (Phase 1) will go to Cloudflare R2.
- **Before real users:** turn `EXPOSE_DEV_OTP` off and wire up an SMS provider. Sending SMS in India requires DLT registration first.
