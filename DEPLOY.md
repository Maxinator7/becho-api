# Deploying the Becho staging environment (free tier)

| Part | Service | Notes |
|---|---|---|
| Database | Neon (free) | 1 GB, scales to zero after 5 min idle |
| API | Render web service (free), from `render.yaml` | Sleeps after 15 min idle; the first request after that takes about a minute |
| Web | Cloudflare Pages (free) | Static Vite build |
| Mobile | Expo Go | `EXPO_PUBLIC_API_URL` points at the Render URL |

This is a **test environment**. OTP codes are shown on screen (`EXPOSE_DEV_OTP=true`), because no SMS provider is set up yet.

## 1. Neon: database
1. Create a project in the **AWS Asia Pacific (Singapore)** region, with Postgres 16.
2. Under **Connect**, turn **Connection pooling OFF** and copy the direct connection string. Prisma migrations need the direct connection.
3. Append `&connect_timeout=15` so the first query after Neon wakes from idle doesn't time out:
   `postgresql://USER:PASSWORD@ep-xxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require&connect_timeout=15`

## 2. Render: API
1. **New → Blueprint**, then connect the GitHub repo `Maxinator7/becho-api`. Render reads `render.yaml`.
2. When prompted, fill in:
   - `DATABASE_URL`: the Neon string from step 1.
   - `CORS_ORIGINS`: the Cloudflare Pages URL from step 3, e.g. `https://becho-web.pages.dev`. If you don't know it yet, enter a placeholder and update it later.
3. Deploy. Every start runs `prisma migrate deploy`, which applies pending migrations. Check that `https://<service>.onrender.com/api/v1/health` returns `"status":"ok"`.

`JWT_SECRET` and `JWT_REFRESH_SECRET` are generated by Render.

## 3. Load the starter data (once, from your machine)
```bash
cd becho-api
DATABASE_URL='<neon string>' SEED_PASSWORD='<a non-default password>' npm run seed
```
This creates the cities, categories, demo listings and three demo users: aarav@example.com, priya@example.com and admin@becho.in. Running it again is safe. The URL is public, so use a real password, not `password123`.

## 4. Cloudflare Pages: web
1. **Workers & Pages → Create → Pages → Connect to Git**, then pick `Maxinator7/becho-web`, branch `main`.
2. Build settings:
   - Framework preset: **Vite** (or None)
   - Build command: `npm run build`
   - Output directory: `dist`
   - Environment variables: `VITE_API_URL=https://<service>.onrender.com/api/v1` and `NODE_VERSION=20`
3. Deploy. `public/_redirects` sends every path to `index.html`, so refreshing on `/listing/123` works.
4. Copy the `*.pages.dev` URL into Render's `CORS_ORIGINS` (Render restarts automatically).

`VITE_API_URL` is built into the bundle, so after changing it, trigger a new Pages deploy.

## 5. Mobile: Expo Go
```bash
cd becho-mobile
EXPO_PUBLIC_API_URL=https://<service>.onrender.com/api/v1 npx expo start
```
CORS doesn't apply to the mobile app.

## Known limits of this setup
- **Cold starts:** the API sleeps when idle, and the first request after that takes about a minute. Render Starter ($7/month) removes this.
- **Background jobs only run while the API is awake.** The in-process scheduler expires listings and offers. Expiry catches up on the next wake-up.
- **No persistent disk on Render.** Image uploads (Phase 1) will go to Cloudflare R2.
- **Before real users:** turn `EXPOSE_DEV_OTP` off and wire up an SMS provider. Sending SMS in India requires DLT registration first.
